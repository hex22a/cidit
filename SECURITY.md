# Security Policy

Protecting user privacy and delivering secure software
is the primary focus of this project.
Community vigilance is highly valued.
Thank You for reporting vulnerabilities responsibly.

## Supported Versions

Only the latest stable version of this project receives active security updates.

| Version           | Supported |
| :---              | :---      |
| **Latest Stable** | Yes       |
| < Older           | ❌ No     |

## Reporting a vulnerability

> [!CAUTION]
> Do not use GitHub issues to report any security vulnerabilities

If you are a security researcher and you believe you have discovered a vulnerability,
please use the "Report a vulnerability" button under the "Security" tab.
Learn more about Private vulnerability reporting feature on
[GitHub docs](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing/privately-reporting-a-security-vulnerability)

### What to Include

To ensure a quick resolution, please provide:

* A clear, descriptive title.
* Step-by-step instructions to reproduce the vulnerability.
* A basic Proof of Concept (PoC) script or payload if applicable.
* The potential impact of the vulnerability.

## Commitment & Process

While resources for this project are limited,
security reports are treated with high priority.

After receiving the report, a Project maintainer will contact The reporter
to validate the issue and coordinate a fix timeline.
Once a patch is ready and released, a public disclosure will be published,
ensuring full credit is given to the discovering researcher.
